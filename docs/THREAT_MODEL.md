# 威胁模型（THREAT_MODEL）

> 针对当前实现（非目标蓝图）的威胁模型。风险等级：H=高，M=中，L=低。

## 1. 资产

- 用户资金与支付授权（Karma）。
- 模型 Key / 聊天工具 token / 连接器凭据。
- 业务数据（商品、价格、库存、回执、客户信息）。
- 审计日志（完整性是合规依据）。
- 平台声誉与用户信任。

## 2. 信任边界

```
用户浏览器 ──HTTPS──> API 服务 ──(无)──> 模型提供方(外部)
                         │
聊天工具 webhook ──token──┘
                         │
                用户自定义功能 ──HTTP──> 外部业务系统(电商/库存)
                连接器/Karma ──HTTPS──> Karma/渠道
```

- 边界 A：用户 ↔ 平台（认证、授权、租户隔离）。
- 边界 B：模型输出 ↔ 执行层（规划与执行分离）。
- 边界 C：用户自定义功能 ↔ 外部网络（SSRF、数据外泄）。
- 边界 D：平台 ↔ 外部支付/渠道（回执真实性）。

## 3. 攻击者与能力假设

- 恶意/被入侵的租户用户：合法凭据，试图越权或跨租户。
- 恶意模型输出 / Prompt Injection：模型被诱导输出危险计划。
- 恶意模块发布者：上传内容诱导安装，试图窃取凭据或数据。
- 外部服务不可信：渠道/支付返回伪造回执。
- 内部运维误操作。

## 4. 滥用路径与缓解

| 威胁 | 路径 | 现有缓解 | 残余风险 |
|---|---|---|---|
| 越权调用 | 直接调 `/gateway/execute` | `can_execute` 角色×风险 | 依赖正确传入 Actor（H→M） |
| Prompt Injection 诱导支付 | 模型计划含 `make_payment` | 支付恒审批 + 网关白名单 | 用户盲目批准（M） |
| 模型计划调用未授权工具 | 模型输出任意工具名 | `_run_model_steps` 白名单过滤 | 仅覆盖聊天路径，直接 API 仍靠网关（L） |
| SSRF | 自定义功能 URL 指向内网 | `validate_url` + 解析检查 + 请求前 `recheck_url` | DNS 重绑定窗口收窄，仍需出网代理（L） |
| 跨租户读取 | 猜测资源 ID | 查询按 `workspace_id` 过滤 | 无对象级 ACL 审计（L） |
| 密钥泄露 | 读取 `settings` | Fernet 加密落库 + 读取脱敏 | 依赖 `KRAMA_SECRET_KEY` 安全（L） |
| 模块携带恶意配置 | 发布模块诱导安装 | 发布脱敏 + min_role | 无代码沙箱、无审核（H） |
| 重复扣款 | 重复支付请求 | 幂等键 + 审批去重 | 并发唯一性未压力验证（M） |
| 伪回执标记成功 | 渠道返回假状态 | 回执核验 | 核验仍信任外部响应（M） |
| 聊天 token 暴力破解 | `/chat/inbound` 猜 token | 哈希比对 + 限流 | 全表扫描待索引（L） |
| 审计被篡改 | 内部写 AuditLog | append-only（无更新/删除接口） | 无防篡改签名（L） |

## 5. 未解决的高风险项

1. **模块无沙箱**：当前模块是纯配置，若开放“代码模块”，必须在进程/容器级隔离 + 权限最小化（当前 H）。
2. **Prompt Injection 无检测**：依赖审批兜底，需对模型输出加注入检测与敏感工具二次确认。
3. **无速率限制覆盖全部接口**：`/chat/inbound` 与 `/gateway/execute` 已限流，登录/其他接口待补。
4. **DNS 重绑定**：已加解析检查 + 请求前复检，完整防护需出网代理 + DNS 钉扎。

## 6. 建议的优先修复顺序

1. 支付/资金链路：并发幂等 + 对账 + 强制人工复核。
2. 密钥加密存储。
3. `/chat/inbound` 限流与 token 哈希存储。
4. SSRF：出网仅允许白名单域名 + 解析后 IP 复检。
5. 模块：先仅允许配置型模块，代码型模块上线前必须沙箱。
