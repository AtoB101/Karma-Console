# 实施计划（从 MVP 到完整平台）

依据 `karma.txt`（总体架构 V2.0）的 Phase 0–8，结合当前代码状态记录。

## 当前状态（2026-10-18）

- 已完成：Phase 1 安全核心 + Phase 2 可靠执行 + Phase 3 核心闭环。
  - 身份认证（API Key）、多租户隔离、角色权限、R0–R4、统一执行网关、审计、幂等、审批、回执核验。
  - 个体商家业务对象：商品（草稿/发布/库存）、订单、库存流水、运单、工作区自由排版功能区、连接器安装。
  - Karma 支付生命周期（支付/退款/对账/争议）、持久化工作流（断点续跑/超时/补偿）、可配置电商 HTTP 回执。
- 未完成：Karma 生产联调、预接真实电商平台、模块沙箱、法务规则、后台调度、部署。

## 后续阶段

- Phase 3 模型路由与 Agent 编排：接入真实模型、结构化意图由模型生成、工具权限声明。
- Phase 4 模块系统：模块隔离（进程/容器）、模块安装/卸载/回滚。
- Phase 5 真实商业闭环：选定一个真实渠道（独立站或社交网店）跑通下单→支付→发货→回执核验。
- Phase 6 业务模块扩展：订单/库存/物流/预约/CRM/报表。
- Phase 7 模块市场与商业化：发布、签名、付费、分成、争议。
- Phase 8 规模化与企业部署：服务拆分、高可用、灾难恢复、成本优化。

## 待产品/法务决策

- Karma 支付 API 合同（鉴权、回调、回执、退款、幂等键）。
- 各地区法规（中国、欧盟等）的支付/营销/消费者保护细则，替换 `seed.py` 中的占位规则。
- 电商渠道（独立站/社交网店）开放平台接入方式与回执凭证。
