# 贾维斯开源系统研究简报（生成式窗口舞台落地依据）

> 研究日期：2026-10-27 ｜ 研究样本：`eadmin2/jarvis_ai`（197★）、`fedcal/open-jarvis`（AGPL）
> 克隆位置：`D:\jarvis-research\`（本地研究目录，不混入主项目）

## 一、为什么研究这两个仓库

用户核心诉求：**一句话生成一个页面（数据面板），旧页面自动滑左排列成窗口序列，「回到上一页」切换，无指令自动收起、后端继续干活**。这与 eadmin2/jarvis_ai 的「/api/summon 全息面板召唤」机制高度同构，其 HUD 前端（单文件 857 行）实现了完整科幻视觉。

## 二、jarvis_ai 关键机制（可直接借鉴）

### 1. 面板召唤协议（一句话生成面板）
- Agent 侧工具 `hud_display`（hermes-plugin/hud_display）：`{media: video|iframe|image, src, title, position: center|left|right}`
- 服务端 `/api/summon` 通过 WebSocket 广播到所有 HUD 屏
- `hud_dismiss`：`{action:"dismiss"}` 清屏
- **设计智慧**：工具 description 要"强势"，让模型优先用面板工具而不是偷偷开隐形浏览器；`position=left/right` 用于多面板分屏（center 大面板 + 左右侧小面板）

### 2. HUD 全息视觉（server/hud/index.html）
- **飞入动画 holoApproach**：从 `translateZ(-800px) rotateX(35deg) rotateY(-20deg) scale(.3) + blur(10px) brightness(2.2)` 弹性（cubic-bezier(.34,1.56,.64,1)）飞到归位——这是"从 Z 深处冲出来"的观感核心
- **入场特效层**：SVG 描边 trace（stroke-dasharray 扫过）+ 四角标记、六边形花纹淡出、扫描线 sweep、RGB 分色闪烁（chromatic aberration）、随机坐标 boot ticker
- **悬浮呼吸** holoIdle：面板 idle 时轻微上下浮动 + 光晕脉动
- **消失动画** holoDismiss：去饱和、blur、飞回 Z 深处缩小消失
- **呼啸音效** holoWhoosh：WebAudio 合成（sawtooth→sine 频率滑升/滑落），无需音频文件
- **背景 dolly**：面板到来瞬间整个 HUD scale(1.02) + brightness(.7)，营造镜头推拉感
- **去重**：同一 summon 8 秒内不重复渲染（WS 重连重放保护）
- **状态环 reactor**：canvas 核心环，按状态（standby/listening/thinking/tool/speaking/error）切换转速/颜色/辉光

### 3. 语音链路（本地自持，替代浏览器 Web Speech 的依赖问题）
- 浏览器 16kHz mono 捕获 → AudioWorklet 下采样 → WebSocket 流式 int16 PCM
- 服务端增量 Whisper（partial_transcript 实时字幕）→ 停止后最终转写 → Agent session 对话（SSE）→ TTS 回传
- **关键工程点**：麦克风需 secure context（本地自签 TLS）；SSE 无 charset 头需强制 UTF-8；TTS PCM 字节边界须缓冲奇数余字节；启动竞态（uvicorn 多 listener）需 race-lock

### 4. 安全模型
- `JARVIS_HUD_TOKEN` 门禁所有 /api/*；浏览器 Origin 白名单 + cookie；**Agent API Key 永不进浏览器**（与我们 owner-only 一致）

## 三、open-jarvis（fedcal）
- 文档型基础设施仓库：跨设备语音（wakeword/whisper/Piper TTS）、AR 眼镜、全息硬件（Looking Glass/Voxon/HYPERVSN）对接
- 对我们的参考主要是**架构分层**（agents/ 目录按设备分：voice/desktop/browser/holo），英文文档多为翻译占位，实现未完整落地

## 四、落地到 Karma Console 的设计映射（已定稿）

| jarvis_ai 机制 | Karma Console 落地方案 |
|---|---|
| summon 面板（media/src/position） | 生成式窗口舞台 `#jvStage`：指令 → 生成**数据窗口**（报表/产品库/客户/订单/任务/库存/系统状态），数据全部走本地真实端点 |
| holoApproach 飞入 | `.jv-pop` 入场：Z 深处弹性飞入 + blur/brightness 褪变 + SVG 描边扫描线 + 品红青霓虹配色 |
| pos-left/right 分屏 | **左侧历史窗口列**：新窗口进主位，旧窗口动画滑左并排（≤6 个），点击可回主位 |
| holoDismiss | `.jv-fade` 收起：全部窗口飞回 Z 深处淡出（空闲 60s 自动触发，后端继续） |
| holoWhoosh + dolly | 窗口出入场 WebAudio 呼啸 + 背景短暂 dolly |
| dedupe 8s | 同键去重，防语音重放 |
| approval cards | 已有请示卡体系（POST /chat/proposal + 授权流），本次不重做 |
| 语音链路（WS whisper） | 下一阶段：本地 STT 端到端接续（本机 whisper），替换依赖外网的 Web Speech |
| HUD_TOKEN/Key 不进浏览器 | 已有（owner-only + 模型 key 加密存储，密钥不回传前端） |

## 五、生产约束（本项目强化点，超样本水平）
- 窗口内容**全部真实数据聚合**（新增 `/workspaces/{id}/analytics/report` 按天桶报表端点，30 天/昨日窗口），不做任何伪造
- 权限边界沿用神经触角体系：每个窗口标注负责 Agent 与数据共享边界
- 回归门禁：pytest + 前端语法 + 真实浏览器端到端验收
