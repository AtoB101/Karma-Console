# 上线门槛与成功标准（对应总纲第 15.3 条与第 19 部分）

> 本文由主控 Agent 制定，作为“什么时候可以上线、怎么算成功”的量化标准。
> 上线 = 安全门禁全绿 + 一条真实业务链路可复现；成功 = 可被用户日常使用的可观测指标达标。

## 1. 上线门槛（15.3）

任一失败即整体不通过，不得宣布上线：

- 安全：越权/跨租户测试全绿；密钥永不落明文日志或模型提示；R2/R3 需授权；危险动作被网关硬阻断。
- 执行：全量 `python -m pytest -q -o addopts=""` 无失败；前端 `node --check` 通过。
- 真实链路：`e2e_scenarios.py`（真实 DeepSeek）10/10 场景通过，含画像→上架归类→库存→接单→报价→支付审批→发货→签收→库存扣减。
- 资金：Karma 生产联调前以官方 API_REFERENCE 对齐 + stub 确定性测试为准；真实扣款需官方联调通过后单独放行。
- 数据：增量迁移可执行，旧库不丢数据；设置可回滚（版本快照）。
- 恢复：断点续跑、超时对账、重复提交去重、失败补偿均有可复现测试。

## 2. 成功标准（19，分母与统计方法）

| 指标 | 定义 | 分母 | 目标 |
| --- | --- | --- | --- |
| 指令落地率 | 一句话指令成功产生可观察效果（不退回兜底或报错） | 当日聊天指令总数 | ≥ 95% |
| 无需人工接管率 | 未触发 must_confirm/needs_reply 的订单全自动完成 | 当日订单总数 | ≥ 60% |
| 回执闭环率 | 发货/签收/收款回执状态由 UNKNOWN 变为确认 | 当日产生回执的外部动作总数 | ≥ 99% |
| 待办处理时效 | 10 分钟未处理升级邮件发出 | 当日 must_confirm 待办总数 | 100% 触发 |
| 平均接线时长 | 客户入站到首条自动回复 | 当日入站会话数 | ≤ 5 秒 |

## 3. 判定规则

- 以上门槛与指标每周在真实环境复测一次，结果写入 `docs/ACCEPTANCE_LOG.md`。
- 测试 Agent 拥有一票否决权；主控不以自述代替证据。
