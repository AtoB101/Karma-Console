## 2. 分阶段路线（建议）

- **Phase 1（已完成）**：安全核心 + 可靠执行垂直切片（网关/风险/审批/幂等/审计/租户）。
- **Phase 2（已完成）**：配置化功能区 + 对话编排 + Karma 客户端 + 模块市场雏形 + 设置/聊天接入。
- **Phase 3（已落地核心）**：目标“个体商家衣食住行”可真实收款与发货——
  - 密钥加密存储、`/chat/inbound` 限流、SSRF 复检（已完成）；
  - Karma 退款/对账/争议接口已对齐官方 API_REFERENCE + 网关工具（已完成，待生产联调）；
  - 电商连接器支持用户配置回执网址（SSRF 防护 + 状态/参考号核验，已完成）；
  - 持久化工作流：断点续跑、超时恢复、失败补偿（已完成）；
  - 自主执行循环：规划→执行→回灌→收尾/澄清（已完成）；
  - 客户记忆与真实外发：Customer/Conversation/Message + Telegram/微信 webhook/Discord/通用（已完成）；
  - 后台调度：Karma 对账 + 超时任务恢复（已完成）；
  - Prompt 注入守卫 + 客户来源敏感动作审批（已完成）；
  - Karma 工作区凭证加密存储与真实客户端（已完成，待生产联调）；
  - 控制台模块市场 UI（已完成，左侧可浏览并一键安装）。
- **Phase 4（扩展，进行中）**：多 Agent 协作、数据分类、可观测性（已落地）；代码型模块沙箱 `run_code` 为子进程隔离（`-I` + 白名单导入 + 超时 + 输出上限 + 瞬态 spawn 重试，不开放为可安装函数，已落地）；平台开放审核：webhook 签名校验已落地（Telegram 明文 secret token + 通用 HMAC-SHA256），平台侧账号审核仍待平台方（待做）；生产部署：Dockerfile + docker-compose(PostgreSQL) + `docs/DEPLOY.md`（已落地，生产实测待做）。
- **Phase 5（平台化）**：开发者控制台、模块审核与生命周期、移动端、消息渠道 SDK 适配器。

## 3. 风险优先级

1. H：资金链路并发幂等 + 对账（一旦真实收款必须）。
2. H：模块无沙箱（开放代码模块前必须解决）。
3. M：密钥明文存储 → 加密/KMS。
4. M：SSRF DNS 重绑定 → 复检 + 出网代理白名单。
5. M：Prompt Injection → 敏感工具二次确认。
6. M：`/chat/inbound` 无限流 → 限流 + token 哈希。

## 4. 需产品决策 / 法律核实 / 外部文档才能继续的事项

- 目标市场与地区（CN/EU/…）的支付、数据、营销合规细则 → 法务。
- Karma 生产环境 API 鉴权/结算/仲裁/真实资金语义 → 客户端已对齐官方 API_REFERENCE（Bilateral）；链上托管锁定与 SDK 签名回执仍需官方联调。
- 电商渠道（独立站/社交网店）回执接口文档 → 各平台开放平台。
- 模块市场的发布审核标准与责任划分 → 产品 + 法务。
- 密钥托管方案（本地加密 vs KMS）→ 部署与安全决策。
